Methods and sources

Transparent calculations. Limited claims.

Mouse equations

For linear input, degrees turned = mouse counts × sensitivity × yaw. Counts per centimeter = DPI ÷ 2.54.

cm/360 = 360 × 2.54 / (DPI × sensitivity × yaw)
Target sensitivity = source DPI × source sensitivity × source yaw
                     / (target DPI × target yaw)
Correction = current sensitivity × mean measured cm/360 / desired cm/360

Yaw is degrees per count at sensitivity 1. The Valve Source SDK 2013 mouse implementation defines default m_yaw 0.022 and applies it to yaw rotation. That source does not establish factors for all games or builds. No unsupported game presets are supplied.

Only turn distance is matched; ADS/zoom, FOV feel, nonlinear scales and acceleration need separate treatment. Example: 800 DPI, sensitivity 1, yaw 0.022 gives 51.9545 cm/360. Changing only DPI to 1600 requires sensitivity 0.5.

Firmware inspection

Microsoft’s UF2 format specification defines 512-byte blocks, three magic values, payload bounds, block indexes and optional family IDs. This reader checks that basic subset for every block and reports numeric family IDs without guessing a keyboard model. It does not validate memory maps, extensions, signatures, overlapping UF2 payloads or bootloader compatibility. Mixed block flags are explicitly unsupported.

Arm/Keil’s Intel HEX reference documents the record fields, additive checksum and addressing used here. Records must have valid lengths/checksums, one terminal EOF and no overlapping data addresses. Empty data containers can be structurally valid. A raw BIN has no universal metadata header.

QMK’s hardware-specific flashing documentation illustrates why a container alone cannot establish device compatibility. This tool has no flash or device-access path.

SHA-256 uses Web Crypto digest; HTTPS or localhost is required. An optional trusted hash compares byte identity, not authenticity by itself. Unknown or unsupported structure never implies that a file is safe or unsafe to flash.

Stereo playback

MDN StereoPannerNode documents the equal-power panner, with −1 left and +1 right. A short oscillator feeds a gain envelope, then the panner. Maximum demo gain is 0.1; the default is 0.02. Digital gain cannot guarantee a safe sound pressure level; start with low system volume.

Audio starts on user interaction, ramps in/out and ends automatically. Stop, page hiding and page exit cancel active/pending playback. Balance is local to this demo. No HRTF, acoustic measurement, hearing assessment or system correction is performed.

Privacy and delivery

No analytics, remote scripts, uploads, account, storage or device access. Reports download only when requested. Selected file names and hashes appear in the optional report, so review it before sharing. No firmware bytes are included. Static assets work on HTTPS hosting or localhost in current desktop browsers. Browsers without Web Crypto can still inspect metadata, but cannot hash/compare. Audio needs Web Audio; measurements depend on user input.
